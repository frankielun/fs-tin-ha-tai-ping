# 0002. Pin the Expo/R3F renderer dependency set

Date: 2026-11-23 · Status: accepted with renderer gate outstanding

## Decision

Use the following exact set for the renderer spike and MVP app. Expo-managed
packages must remain on the SDK 54-compatible versions emitted by
`npx expo install --fix`; do not mix SDK 55+ or SDK 58 packages into this app.

| Package | Pinned version | Reason |
|---|---:|---|
| `expo` | `54.0.38` | Latest SDK 54 patch available at pin time |
| `react-native` | `0.81.5` | Expo SDK 54's paired React Native release |
| `react` | `19.1.0` | Expo SDK 54's paired React release |
| `expo-gl` | `16.0.10` | SDK 54 bundled native module set; provides `GLView`/WebGL2 context |
| `@react-three/fiber` | `9.3.0` | Stable R3F release with native entry point |
| `three` | `0.179.1` | Stable Three.js release compatible with R3F 9.3 |
| `@react-three/drei` | **not installed** | Not needed for the spike: all required geometry/materials/camera work uses Three core; omitting it reduces native bundle and transitive dependency risk |
| `typescript` | `5.9.2` | Expo SDK 54 changelog recommendation |
| `jest` | `29.7.0` | SDK 54 dependency validation requirement |
| `jest-expo` | `54.0.18` | SDK-matched Jest preset |
| `react-test-renderer` | `19.1.0` | Matches React 19.1 |
| `@types/react` | `~19.1.10` | SDK 54 template-compatible types |
| `@types/three` | `0.179.0` | Types matching the pinned Three minor |

The root app should use the same versions, but this ADR does not modify the
root package manifest. The isolated spike records its own lockfile.

## Compatibility evidence

### Expo and React Native

Expo's SDK 54 package metadata (`expo@54.0.38`) declares React Native
`0.81.5` and React `19.1.0` as its development pair. The SDK 54 release notes
confirm "React Native 0.81 with React 19.1", recommend TypeScript `~5.9.2`,
and state that SDK 54 is the final release that supports opting out of the New
Architecture.

Sources:

- [Expo SDK 54 release notes](https://expo.dev/changelog/sdk-54)
- [React Native 0.81 release notes](https://reactnative.dev/blog/2025/08/12/react-native-0.81)
- [React Native 0.81.5 platform floor source](https://github.com/facebook/react-native/blob/v0.81.5/packages/react-native/scripts/cocoapods/helpers.rb)
- [Expo SDK package metadata](https://registry.npmjs.org/expo/54.0.38)
- [SDK 54 bundled native modules](https://raw.githubusercontent.com/expo/expo/sdk-54/packages/expo/bundledNativeModules.json)

### GL path

`expo-gl@16.0.10` is the SDK 54 bundled module. Its official package metadata
has peer dependencies on Expo, React, and React Native, with no incompatible
version restriction. Expo's GLView documentation states that it creates an
OpenGL ES render target on Android and iOS and exposes a WebGL2-like context.
R3F's native package entry point targets React Native and its peer range
requires Expo `>=43`, React Native `>=0.78`, React `>=19`, Three `>=0.156`,
and `expo-gl >=11`; the pinned set satisfies all of those constraints.

Sources:

- [Expo GLView documentation](https://docs.expo.dev/versions/latest/sdk/gl-view/)
- [expo-gl package metadata](https://registry.npmjs.org/expo-gl/16.0.10)
- [R3F 9.3.0 package metadata](https://registry.npmjs.org/@react-three/fiber/9.3.0)

### Three and R3F

R3F 9.3.0 accepts Three `>=0.156`; Three `0.179.1` is therefore within its
declared peer range. R3F 9.3.0 accepts React Native `>=0.78`, so RN 0.81.5 is
covered. The spike deliberately excludes Drei because no Drei primitive is
required and Drei would add a large helper/transitive dependency surface to a
renderer whose first gate is frame time and memory.

Sources:

- [R3F 9.3.0 package metadata](https://registry.npmjs.org/@react-three/fiber/9.3.0)
- [Three.js package metadata](https://registry.npmjs.org/three/0.179.1)
- [R3F native implementation](https://github.com/pmndrs/react-three-fiber/tree/v9.3.0/packages/fiber/src/native)

## Platform and architecture constraints

- Product floor remains iOS 15+ and Android API 26+, but the exact native
  minimum generated by this set is iOS **15.1** (React Native 0.81.5) and
  Android API **24**; the product's API 26 floor is therefore stricter than
  the framework minimum. Expo SDK 54's supported-build matrix and the
  app-store submission rules must be checked by fs-devops before distribution.
  Do not infer that a current store submission accepts the historical floor.
- SDK 54 is the final Expo line with a Legacy Architecture opt-out. The
  approved spike uses **New Architecture on** (`expo.newArchEnabled: true`),
  because the renderer and current Expo/RN ecosystem are moving in that
  direction. A Legacy Architecture fallback is a compatibility experiment,
  not a second supported production set.
- Do not use `use_frameworks!`: SDK 54's precompiled React Native iOS
  frameworks are incompatible with it and fall back to a source build.
- `expo-gl` is an OpenGL ES/WebGL2 bridge, not Metal/Vulkan. The spike must
  exercise the actual native GL path in release builds; a web preview or debug
  render does not satisfy the gate.
- Expo docs state that remote debugging does not work correctly with GLView;
  performance runs must use the device/emulator JavaScript runtime.
- This set is a feasibility pin, not permission to add physics, post-processing,
  HDR textures, or an unbounded particle system.

## Performance spike and measurement status

The throwaway implementation lives in
[`.scratch/mvp/spike-r3f`](../../.scratch/mvp/spike-r3f/README.md). It has a
portrait scene, low-poly fortress, shield dome, pooled projectile, pooled
instanced burst, a 10-second repeated loop, and an on-screen FPS/JS-heap
readout.

On 2026-11-23 this host could not complete the requested native release
builds:

- iOS: `npx expo run:ios --configuration Release` generated the native
  project and installed CocoaPods, then stopped because Xcode is not fully
  installed/selected. Direct `xcrun simctl list devices available` reports
  `unable to find utility "simctl"`.
- Android: `npx expo run:android --variant release` generated the native
  project, then stopped with `Failed to resolve the Android SDK path` and
  `Error: spawn adb ENOENT`.

Therefore there are **no measured FPS, frame-time, or memory numbers** for an
iOS simulator, Android emulator, or physical device in this report. The
spike's typecheck, dependency resolution, and JS bundle checks are useful
static evidence only; they are not a performance result.

Required follow-up, owned by fs-qa:

1. Install/select Xcode and an iPhone 11-class iOS simulator, then build a
   Release configuration and capture 10 seconds of frame times with the
   overlay plus Instruments Core Animation/Time Profiler and Allocations.
2. Install Android SDK/emulator and a Pixel 6a-class API image, then build a
   Release APK, capture the same run, and record `adb shell dumpsys meminfo`
   before/after and frame timing from Android GPU Inspector or
   `dumpsys gfxinfo`.
3. Repeat on physical iPhone 11/A13-class and Pixel 6a-class devices. The
   simulator/emulator runs are directional only and cannot satisfy the ADR
   kill criterion.
4. Record average FPS, minimum FPS, p50/p95/p99 frame time, JS/native peak
   memory, OS/build image, thermal state, and whether the complete loop ran
   without a dropped GL context.

## Perf budgets for tickets 04–07

These are hard budgets, not targets to average away:

- **Frame gate:** at least 55 FPS for the complete repeated 10-second
  fire-and-shatter sequence; no sustained frame below 18.18 ms at the 55 FPS
  gate, and investigate any p95 over 16.67 ms.
- **Memory gate:** peak process memory at or below 250 MB on each floor device.
- **Particles:** maximum 192 live burst particles total, with a fixed pool;
  reset/reuse slots rather than allocating objects or arrays during a burst.
- **Projectile pool:** maximum 4 live projectiles; no mount/unmount cycle per
  shot.
- **Mesh budget:** the fortress plus shield and projectile scene should remain
  below 5,000 rendered triangles in the MVP fire view, excluding the
  instanced particle geometry. Every new mesh needs a measured triangle count.
- **Draw discipline:** prefer instancing for repeated particles and shared
  materials/geometries; avoid per-particle materials and avoid runtime
  geometry generation.
- **React discipline:** no per-frame React state updates, props churn, or
  component tree reconciliation. Per-frame animation belongs in `useFrame`
  and mutable refs/Three objects.
- **Allocation discipline:** no per-frame allocations in the hot loop; pool
  vectors, colors, effect records, and timers. Dispose GPU resources exactly
  once on unmount.
- **Readout discipline:** the FPS/memory overlay is diagnostic only and must
  not be used as the measurement source or left enabled in production.

## Verdict

**RENDERER BLOCKED: native release performance evidence is unavailable on this
host (no Xcode simulator and no Android emulator/ADB); escalate to
fs-architect for gate disposition, and do not treat tickets 04–07 as
renderer-unblocked.** The package graph provides the required Expo GL path on
paper and is ready for fs-qa's release-build run. If two optimization passes
on both physical floor devices fail 55 FPS or exceed 250 MB, supersede this
ADR and reassess Unity while preserving the engine and `SceneAdapter`
contracts.
